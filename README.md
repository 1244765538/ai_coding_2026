# 🚀 2026 工作室 AI Coding 考核任务

欢迎参加本次 AI Coding 考核。本次考核不测试你的“手速”，而是测试你**“指挥 AI 解决实际问题”**的能力。

请仔细阅读以下指南，并严格按照要求完成并提交代码。

## 📁 项目结构说明

Fork 本仓库后，你将看到以下目录：
*   `baseline/`：**你的主战场**。请在这里完成代码编写，并在对应的 `README.md` 中查看具体业务需求。
*   `sample_testcases/`：提供的公开测试数据，你可以用来本地调试。
*   `AI_dialogue.md`：**AI 协作记录模板**。你的所有与 AI 的交互记录（复制文本或截图）必须填写在这里。
*   `run_instructions.md`：**运行说明**。你需要在这里写清楚如何启动你的代码、依赖了哪些第三方库。

## ⚠️ 核心考核点（必看）

1. **结果导向**：你的代码必须能跑通基础流程。
2. **过程追溯**：**这是重中之重！** 我们不看“最终完美版代码”，我们要看你是如何拆解需求、如何向 AI 提问、如何排查报错的。如果 `AI_dialogue.md` 为空或明显造假，直接按不及格处理。
3. **异常处理**：不要只写 Happy Path（顺利路径），请考虑空值、非法输入、重复提交等边界情况。

## 🛠️ 交卷流程（Git 保姆级指南）

如果你还不熟悉 Git 的 Fork 和 PR 流程，请严格按以下步骤操作（**禁止直接把代码发在微信群里**）：

### 第一步：Fork（复刻）仓库
打开本仓库页面，点击右上角的 **Fork** 按钮，将项目 Fork 到你自己的个人账号下。

### 第二步：Clone（克隆）到本地
打开你的终端（或 Git Bash），执行：
```bash
git clone https://github.com/你的用户名/ai_coding_2026.git
cd ai_coding_2026
```

### 第三步：本地开发
在 `baseline/` 中编写代码，测试通过后，**千万不要忘记填写 `AI_dialogue.md` 和 `run_instructions.md`**。

### 第四步：提交代码（Commit & Push）
请在终端中执行以下命令（**必须至少提交 2 次**，让我们看到你的修改过程，不要一次性把代码全梭哈）：
```bash
# 第一次提交（完成基础代码后）
git add .
git commit -m "feat: 完成基础业务逻辑"
git push origin main

# 第二次提交（完善 AI 记录和补充边界情况后）
git add .
git commit -m "docs: 补充 AI 对话记录及运行说明"
git push origin main
```

### 第五步：发起 Pull Request（PR）
1. 回到你 GitHub 上的仓库页面，点击 **Pull requests** 标签页，然后点击 **New pull request**。
2. 确保左边是你的仓库，右边是原仓库的 `main` 分支。
3. **PR 的标题格式必须是：`姓名_学号_交卷`**（例如：`张三_2023001_交卷`）。
4. 在描述里简要写一句：“已按考核要求完成并提交代码及 AI 记录。”
5. 点击 **Create pull request** 提交。

*(注：如果你在本地 Git 操作中遇到报错，如 `src refspec main does not match any`，请先检查是否漏了 `git add` 或 `git commit` 步骤。)*

## 🚨 避坑与扣分项

*   **严禁直接复制**：如果发现代码雷同，或 PR 记录与 AI 对话记录完全对不上，双方均按 0 分处理。
*   **不要提交垃圾文件**：请千万不要把你本地生成的 `.venv`、`__pycache__`、`.idea` 等环境缓存文件夹提交上来，仓库里已经配置了 `.gitignore`，提交前请确认。
*   **环境统一**：请尽量使用 Python 3.10 或 Node 18 版本进行开发，以防止运行环境不兼容。

如果你在 Fork 或 Git 推送环节彻底卡死，且无法在群里求助解决，请将你的完整项目打包成 `姓名_学号_备份.zip`，发送至邮箱 `你的邮箱@xxx.com`。但请注意，**通过 Git PR 交卷的同学，平时分/过程分会更高**。
